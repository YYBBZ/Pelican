> 定时让模型画同一张图，从它画成什么样，看出这个号池有没有降智。

## 为什么会有这个 App

现在的中转站基本都是号池：一堆共享账号拼起来对外提供接口。账号的 IP 干不干净，直接决定模型状态——IP 被判定可疑，GPT 就容易「降智」：回答变短、逻辑变浅、复杂的活干不动，但接口照样返回 200，表面上一切正常。

这种退化不报错、不打日志、不告警。你只能在使用中感觉「今天怎么这么笨」，却说不清是哪条线路、从什么时候开始、掉了多少。

Pelican 就是干这件事的：把「感觉变笨了」变成曲线上一个明确的掉头。

## 怎么测

思路很简单：出一道有标准答案的题，看它还画不画得出来。

每次检测让模型用 SVG 画指定的图——英文鹈鹕、中文「鹈鹕」、土星环上的鹈鹕、加菲猫，要求纯代码绘制。模型越清醒，产出的结构越完整、路径越细腻、用色越丰富；一旦降智，最先崩的就是这种「既要看懂又要精确执行」的活：画一半截断、退化成几个色块、或者干脆写字糊过去。

拿到返回后在本地解析：

- 必须能被 SVG 解析器正常解析，`</svg>` 完整收尾
- 按节点数、路径总长度、颜色数量、是否含文字，算一个 0–100 的综合分
- 全程本地计算，不把内容发给第三方评分服务

## 怎么判「这一次算不算降智」

单次分数低说明不了什么，模型本来就有波动。所以用的是自校准基线：

以最近 5 次成功结果的**中位数 × 0.8** 作为自动下限，再乘 0.5–1.5 的倍率（默认 0.9），超过 100 按 100 封顶。低于这条线记为可疑。也可以手动填固定下限，手动值不乘倍率，直接生效。

四种状态：

- **PASS** — 正常
- **SUSPECT** — 分数低于下限，可疑
- **ERROR** — 返回异常：解析不了、被截断、作弊、模型回显不符
- **FAIL** — 请求本身失败

编辑页、监控页、历史记录用的是同一套算式和同一个生效值，不会出现「编辑时显示 72 分及格，实际按 80 分判」的情况。

## 防糊弄

偷懒是有套路的，专门盯着这几种：

- 贴位图（`<image>`）——不是画的，塞了张图
- 用文字代替（`<text>` / `<tspan>`）——写「这是一只鹈鹕」完事
- 引用外部素材（`href` 指向 http）——外包出去画
- 塞脚本（`<script>` / `<foreignObject>`）

命中任一条直接判 ERROR，不进基线、不污染后续分数。除此之外还会核对响应里回显的模型名是不是你请求的那个——有些站会把请求悄悄转到更便宜的模型上。

## 输入异常筛查

中间人有机会在请求里动手脚。所以每轮都会拿回报的 token 数和本地估算对比：数量模式默认超 800、倍率模式默认超 5 倍，任一命中就在卡片上标一个蓝色「注入」。

这是**疑似**，不是确证——所以它单独归类，不弹通知、不计入连续质量异常。详情里会把估算值、回报值、差额和命中的规则全部摊开，信不信由你判断。

## 多线路各算各的

一条线路是一套独立配置：地址、key、模型、间隔、题目顺序、基线、倍率。

三条线路的基线互不影响，这点很关键——便宜模型和旗舰模型的正常水平本来就不在一个量级，混着算基线等于全错。支持 OpenAI Chat、Responses、Anthropic Messages 三种接口形态，模型列表可以直接拉。

## 功能

- **定时监控** — 后台服务运行，间隔自定，从本轮结束后开始计时
- **题目顺序表** — 内置四道题，可自己加；顺序按线路保存，可拖动、上下移；下一轮标在首位，轮内锁题，任一请求完整返回就前移
- **多轮样本** — 每轮 1–99 个样本，失败可补试 0–20 次；补试超过 5 次会提示重复计费
- **思考强度** — auto / none / low / medium / high / xhigh / max 七档，中英双标；auto 不下发参数；需要预算时 xhigh 32000、max 64000
- **趋势图** — 纯 SVG 绘制的分线路曲线，支持缩放与横屏
- **原始记录** — 每轮的 SVG 完整保留，可导出回看；不放心分数就自己看画成什么样
- **通知** — 只在连续质量异常时提醒，单次波动不打扰
- **备份恢复** — 整库导出与导入
- **旧数据迁移** — 老版本历史升级后本地重判，不调接口、不产生费用、不改基线

## 数据在哪

历史、配置、基线全部只存在手机本机。除了你自己填的线路地址，App 不连任何第三方服务器：没有统计上报，没有云端同步，也没有账号体系。

## 安装

到 [Releases](https://github.com/YYBBZ/Pelican/releases) 下载 APK，约 5.1 MiB。

包名 `app.pelican.monitor`，versionCode 8，支持 Android 8 以上。沿用 2.3 / 2.2 签名，可直接覆盖升级，历史、线路、基线保留；升级前建议先导出备份，不要卸载。

## 构建

```bash
bash scripts/build.sh
```

需要 JDK 17、aapt2、D8/R8、zipalign、apksigner；Java API 35，目标 API 34。依赖 jar 在 `app/libs`，开源许可在 `app/src/main/assets`。签名私钥不在仓库内。

## 验证边界

253 项本地逻辑与回环检查、16 组 Android JVM / SQLite 验收通过；13 次真实短生成完整返回。

Android 16 的 JVM 兼容尝试因 Robolectric 缺少 Linux ARM 原生库而阻塞，未计入通过项。**没有**做真机安装验收，也没有做实际桌面渲染和长时间后台运行验证。

最后说一句：这些分数给的是趋势和可疑信号，不是对某个模型的权威结论。分数低不等于一定降智，也可能是它今天就是不想画。
