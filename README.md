# Pelican

一个装在手机上的小工具，用来长期盯着中转站里的 GPT 到底聪不聪明。

它的做法很朴素：隔一段时间让模型画同一张图，然后看画出来的东西有多完整。画得越来越简单，就说明这条线路开始降智了。

## 背景

现在的中转站，底下大多是一堆账号拼成的号池。这些账号的 IP 干不干净，站方自己未必清楚。IP 一旦被判定为可疑，模型的输出质量就会明显下滑：回答变短、思路变浅、稍复杂的任务直接敷衍过去。

麻烦的地方在于，这种下滑没有任何外部信号。接口照样返回 200，日志里什么也看不出来。用户只能在使用中感觉到不对劲，却说不清是哪条线路、从哪天开始、掉了多少。

Pelican 就是把这件模糊的事变成可以查的记录：每次检测存一条，分数掉下去能看见，趋势画出来也能看见。

## 为什么用画画来测

聊天类的问题不好用作标准。同一个问题，状态好的模型和降智的模型给出的答案可能都"看着像对"，你很难有客观依据去比。

画画不一样。要求模型用代码画一只有细节的鹈鹕（也有中文题、土星环、加菲猫几种），它必须同时理解题意并精确执行。脑子清楚的时候，结构完整、路径细腻；一旦状态下滑，最先出问题的就是这类任务——画到一半断掉、退化成几个色块，或者干脆写两个字交差。

这些差别用不着人眼看，程序就能算。

## 分数是怎么来的

拿回来的 SVG 先在本地解析：能不能正常解析、`</svg>` 有没有完整收尾，然后统计节点数量、路径总长度、颜色种类，加权算出一个 0–100 分。

整个过程在手机上完成，不把内容发给第三方去评分。

## 多少分算不正常

单次分数低说明不了问题，模型本来就有波动。所以判断用的是它自己的历史水平：

取最近 5 次成功结果的中位数，打八折，再乘一个可调倍率（默认 0.9），得到的值作为下限。低于这条线下判为可疑。也可以手动填一个固定下限，手动值不再乘倍率。

结果分四种：PASS 正常，SUSPECT 低于下限，ERROR 返回内容有问题，FAIL 请求本身失败。

这个算式在编辑页、监控页和历史记录里用的是同一套，显示的生效值也一致，不会出现设置页和实际判定对不上的情况。

## 防糊弄的检查

模型偷懒有固定套路，程序会逐项检查返回内容里有没有这些东西：

- 用 `<image>` 贴位图冒充绘制
- 用 `<text>` 写字代替图形
- 引用外部链接的素材
- 夹带 `<script>` 或 `<foreignObject>`

命中任何一条直接判 ERROR，不计入基线，也不会影响后续的分数对比。

另外还会核对响应里回显的模型名。有些中转站会把请求转给更便宜的模型，回显对不上同样判 ERROR。

## 输入异常筛查

请求在传输途中被人加料是有可能的。每轮检测都会把返回的 token 用量和本地估算做个比较，数量模式超过 800、倍率模式超过 5 倍，就在卡片上标一个蓝色的「注入」。

这只是疑点，不是证据。所以它单独归一类，不弹通知，也不算进连续质量异常。详情里会列出估算值、实际值、差额和命中的规则，怎么判断交给你。

## 多条线路各自独立

一条线路对应一套配置：地址、密钥、模型、检测间隔、题目顺序和基线，都互不干扰。

基线分开算是必须的。便宜模型和旗舰模型的正常水平差着量级，混在一起比，结论一定是错的。

接口形态支持 OpenAI 的 Chat、Responses 和 Anthropic 的 Messages，模型列表可以直接拉取。

## 其他功能

- 后台定时检测，间隔自己设定，从上一轮结束后开始计时
- 内置四道画图题，也可以自己加；顺序按线路保存，支持拖动调整，下一轮使用的题目排在首位
- 每轮可跑 1–99 个样本，失败的可以补试，最多 20 次（补试次数多时会提示重复计费）
- 思考强度七档，中英文并列显示；选 auto 时不传该参数
- 趋势图用 SVG 绘制，支持缩放和横屏
- 每一轮的原始 SVG 都保留，可以导出回看，不认同分数就自己看画
- 只在连续出现质量问题时才通知，单次波动不打扰
- 整个数据库支持导出和导入
- 老版本的历史在升级后本地重新判定，不重新请求接口，不产生费用

## 数据存放在哪

历史、配置和基线都只保存在手机本地。除了你自己填写的线路地址，App 不连接任何其他服务器，没有统计上报，也没有账号体系。

## 安装

APK 在 [Releases](https://github.com/YYBBZ/Pelican/releases) 下载，约 5.1 MiB。

包名 `app.pelican.monitor`，versionCode 8，支持 Android 8 及以上。签名与 2.3 版本一致，可以直接覆盖安装，历史、线路和基线都会保留。安装前建议先导出一份备份，不要卸载重装。

## 构建

```bash
bash scripts/build.sh
```

需要 JDK 17、aapt2、D8/R8、zipalign 和 apksigner，Java API 35，目标 API 34。依赖 jar 放在 `app/libs`，许可文件在 `app/src/main/assets`。签名私钥没有放进仓库。

## 已知的边界

253 项本地检查和 16 组 Android JVM / SQLite 验收已通过，13 次真实短生成也都能完整返回。

Android 16 的兼容性验证卡在 Robolectric 缺少 Linux ARM 原生库，未计入通过项。真机安装验收还没有做，实际桌面渲染和长时间后台运行也没有验证。

最后需要说明的是，这些分数反映的是趋势和疑点，不是对模型的定论。分数低未必是降智，也可能只是这次没画好。
