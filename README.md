# Pelican

一个装在 Android 手机上的小工具，用来定时检查模型接口的输出，长期观察中转线路的质量和稳定性。

它会按设定的顺序让模型绘制 SVG，记录返回内容、复杂度分数、耗时和 Token 用量。怀疑某条线路最近不太对劲时，可以翻历史、看趋势，也可以直接打开当时生成的图，而不只凭一次聊天的感觉判断。

[下载安装包](https://github.com/YYBBZ/Pelican/releases/latest) · [构建说明](docs/BUILDING.md) · [2.4 发布记录](docs/RELEASE-2.4.md)

## 为什么做这个

有些中转线路背后是账号池。同一个模型名、同一个接口地址，不同时间返回的内容可能有明显差别：有时细节丰富，有时明显简化，也可能频繁断流或失败。

我想把这些变化留下来，方便长期观察，而不是测完一次就没有下文。Pelican 主要做的就是定时检测、多线路对比和历史记录。

它不能查明账号或 IP 的真实状态，也不能单靠一张图确定模型是否“降智”。分数有变化，是值得继续核查的线索，不是对原因的定论。

## 怎么检测

内置题目包括鹈鹕骑自行车（英文、中文）、土星环上的鹈鹕、加菲猫骑缅因猫，也可以添加自己的题目。

每条线路有独立的题目顺序。按轮次依次出题，跑完一遍后循环；同一轮的所有样本使用同一道题。一轮里只要有样本完整返回，就推进到下一道题；整轮请求全部失败则保留原来的题目。SVG 无效或命中输入异常，不会单独阻止顺序前进。

比较时按线路、模型和题目分组，避免把不同任务的分数直接混在一起。

## 分数怎么看

App 会在本地检查 SVG 是否完整、能否解析，再根据节点数量、路径数据量、颜色种类等指标，计算一个 0–100 的复杂度分数。这里的“路径数据量”指路径描述的字符量，不是图形的实际几何长度。

这套评分不需要另外调用一个模型，但也不会真正理解画面。元素堆得多不一定画得对，画得简洁也不一定能力差，所以最好结合原图和多次结果一起看。

自动下限按每组最初收集到的 5 轮合格结果建立：

```text
基础下限 = 5 轮分数的中位数 × 0.8（保留一位小数）
生效下限 = 基础下限 × 可调倍率（默认 0.9，最高按 100 生效）
```

基线形成后不会随每一轮自动滚动更新，不是“始终取最近 5 次”。也可以手动设置固定下限；设置后不再乘倍率。

最终状态有四种：

- **PASS**：本轮检查通过，不代表模型身份或能力已经得到认证。
- **SUSPECT**：至少一张样本低于生效的复杂度下限。
- **ERROR**：返回内容异常、回显模型名不一致，或命中输入异常规则。
- **FAIL**：请求失败、配置不完整或检测中断。

## 返回内容检查

除了分数，还会检查 SVG 有没有以下内容：

- `<image>` 位图
- `<text>` / `<tspan>` 文字元素
- 通过外部链接引用的素材
- `<script>` / `<foreignObject>`

这些是当前绘图测试不接受的内容，并不意味着它们在所有 SVG 中都不合法。命中后会判为异常，不用来建立基线。

App 也会核对接口回显的模型名。名字不一致时会提示异常；名字一致，不能反过来证明服务端没有换模型。

## 输入 Token 异常筛查

App 会保留实际请求的核验信息，把本地估算与接口回报的输入 Token 数量比较。两种判定方式选一种，阈值都可以修改：

- **按数量**：接口回报量 − 本地估算量 **大于 800 Token**，默认判为异常。
- **按倍率**：接口回报量 **大于等于本地估算量的 5 倍**，默认判为异常。

本地估算不可用或为 0 时，改用“接口回报的输入 Token 数大于请求正文的 UTF-8 字节数”作为辅助规则。缺少有效用量或请求依据时，显示“无法判定”，不当作正常通过。

命中规则后，历史卡片会显示蓝色的“注入”标识，本轮状态为 ERROR。详情会列出估算量、回报量、差额、规则和结果。

**这只是疑似输入异常，不是注入的确证。** 本地估算、协议封装和服务端计数方式都可能影响比较结果；未命中也不能证明没有注入。只有输入异常时，不计入连续质量异常，也不发送质量告警通知。

## 还有哪些功能

- 多条线路分别保存地址、密钥、模型、检测间隔和题目顺序。
- 支持 OpenAI Chat Completions、Responses 和 Anthropic Messages 接口，可获取模型列表；具体兼容程度仍取决于服务端。
- 后台定时检测，间隔从上一轮结束后开始计算。
- 每轮 1–99 个样本，本轮最多补试 0–20 次；仅临时故障重试，补试可能再次计费。
- 思考强度支持 `auto / none / low / medium / high / xhigh / max`；选择 auto 时不发送该参数，其他档位按协议支持情况发送或换算。
- 监控页显示当前进度，历史详情可查看正在返回的内容。
- 趋势图支持分组对比、横向缩放和横屏查看，时间轴可按检测次数或实际时间排列。
- 保留生成的 SVG，支持导出；历史支持筛选、多选和批量管理。
- 支持备份恢复，以及旧历史的本地输入异常重判；重判不重新调用接口，也不产生接口费用。

检测会实际调用你配置的接口，费用由对应服务商收取。后台能否长期稳定运行，也受系统省电策略和网络状况影响。

## 数据与隐私

线路配置、基线和历史保存在手机本地，没有云端历史同步服务。生成请求会发送到你自己配置的接口，不另外上传给第三方评分。

请妥善保管密钥、导出的备份和检测记录；“保存在本地”不等于这些内容已经加密，也不代表做过完整的安全审计。

仓库中的历史测试站点已用示例地址替换，详见 [验证资料说明](verification/README.md)。

## 安装与构建

在 [Releases](https://github.com/YYBBZ/Pelican/releases) 下载 APK。当前发布版为 2.4，包名 `app.pelican.monitor`，versionCode 8，支持 Android 8 及以上。

2.4 发布记录显示其签名与 2.3 一致。其他来源或更早版本能否覆盖安装，要看包名和签名是否匹配；安装前建议先备份，不要先卸载旧版。

源码的构建环境、工具路径和签名配置见 [构建说明](docs/BUILDING.md)。工程是在 APK 恢复源码的基础上继续开发的，附带的 Gradle 配置为恢复配置，当前发布构建使用 `scripts/build.sh`。发布签名私钥不在仓库中，自行生成的签名不能直接覆盖官方发布版。

## 验证情况

现有 2.4 发布记录报告：253 项本地检查、16 组 Android JVM / SQLite 验收通过，13 次真实短生成完整返回。这些数字是该版本的历史记录，不是每次文档更新后都会重新跑出的结果。

Android JVM 验收使用 Robolectric，不等于真机验收。Android 16 框架检查受 Linux ARM 原生库缺失阻塞，未计为通过；实际手机安装、画面和手势、长时间后台运行仍需另外验证。
