# 验证资料说明

这里包含本地检查程序、历史真实接口样本，以及 2.4 发布时记录的结果。它们用途不同，请分别看待。

## 目录与用途

- `RecoverySmokeTest.java`、`PelicanRegressionTest.java`：使用本地合成响应，不请求真实中转站。
- `LocalTransportTest.java`：只连接本机回环 HTTP 服务，核对发送字节和流式回调。
- `check-contracts.py`：检查源码约定、数据库表和关键配置。
- `android-runtime/`：Robolectric / SQLite JVM 测试，以及已保存 SVG 的解析回放；不是完整的真机验收。
- `archive-2.2/`、`archive-2.3/`：历史版本检查程序，不保证适用于当前源码。
- `v2.3/`、`v2.4/`：对应版本的真实接口联调程序和历史输出。
- `final-result.json`：2.4 发布时的结果汇总，不代表其他版本，也不会因文档更新自动刷新。
- `Pelican.apk.sha256`：GitHub Release 中 `Pelican-2.4.apk` 的校验值。

## 公开副本做了哪些脱敏

历史站点域名已分别替换为 `relay-a.example.invalid`、`relay-b.example.invalid`、`relay-c.example.invalid`，相关文件名也改用中性的线路标识。这些地址是占位，不是可调用的服务。

响应里的模型名是服务端当时提供或回显的标识，不是对真实模型身份的认证。为避免破坏请求字节核验，样本内的模型别名、请求正文、字节数量、哈希、生成内容和计数没有为美观而改写。

脱敏的历史结果仍是历史结果，不是对示例域名做过测试。`test-authorization.json` 也只保留当时的测试背景，**不授权任何人继续调用旧站点或无限消耗额度**。

上述清理针对当前分支的文件。旧提交、旧标签或外部缓存可能仍保留之前的文本；普通提交不能抹除历史。这次没有强制推送或重写版本历史。

## 手动真实接口测试

构建脚本不会自动运行这里的真实接口联调程序。不要直接照搬历史测试次数和额度，更不要把真实密钥填进 Java 或 Python 源码。

这些程序现在要求显式设置：

- `PELICAN_TEST_BASE_URL`：你有权使用的 HTTPS 接口地址；不会再默认连接历史站点。
- `PELICAN_TEST_MODEL`：要测试的模型名，生成测试时必须提供。
- `PELICAN_TEST_OUTPUT_DIR`：可选，新输出目录。默认写入被 Git 忽略的 `verification/local/` 对应版本子目录，不覆盖仓库中的历史样本。

Java 联调程序编译时需同时包含 `verification/ManualTestConfig.java`，它负责上述显式配置校验。

密钥仍通过命令行参数指定的本地文件读取，不要将密钥本身放进命令行或提交到仓库。旧程序的模式和参数并不完全一致，调用前先阅读对应源码；生成测试会收费。

各 Java 联调程序通过 `-Dpelican.root=...` 指定仓库根目录，未指定时使用当前工作目录。Python 检查则从脚本位置定位源码，避免绑定原作者机器上的绝对路径。

`scripts/` 中的历史补丁程序同样只供追溯开发过程，不属于验收步骤。

## 验证范围

2.4 历史汇总记录了 253 项本地检查、16 组 Android JVM / SQLite 验收，以及 13 次完整返回的真实短生成。具体覆盖范围见 `../docs/RELEASE-2.4.md`。

本次公开仓库整理另外做过的检查见 [整理检查记录](PUBLIC-CLEANUP.md)，与发布时的真实接口测试分开记录。

计数检查、SVG 可解析、接口成功返回，不等于模型能力已经得到认证。Android 16 框架检查曾因 Linux ARM 原生库缺失被阻塞；真机安装、实际画面与手势、后台长期运行也没有被这些历史结果替代。

`.log` 文件默认不进入仓库，因此发布说明提到的所有本机构建日志并不一定包含在公开源码中。判断通过范围应结合现存的汇总、测试源码和样本，不把不存在的日志当作已提供的证据。
